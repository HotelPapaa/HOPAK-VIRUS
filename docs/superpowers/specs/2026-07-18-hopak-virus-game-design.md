# HOPAK VIRUS 게임 디자인

## 1. 목적과 제약

`HOPAK VIRUS`는 Unity 6.3 LTS Universal 3D로 제작하는 3인칭 3D 액션 게임이다. 플레이어는 호팍 바이러스 감염자 0호가 되어, 어색하고 어려운 호팍 이동으로 적에게 접근한 뒤 짧은 사거리의 바이러스를 발사해 모두 감염시킨다.

핵심 재미는 별도의 공격 콤보가 아니라, A와 D로 양발의 박자를 맞춰야만 전진할 수 있는 이동 자체에서 나온다. 어렵게 확보한 거리와 위치가 곧 전투 자원이다. 공격은 이동 리듬과 분리하여 언제든 동일한 성능으로 사용할 수 있게 한다.

필수 제약은 다음과 같다.

- Unity 버전은 현재 프로젝트의 `6000.3.20f1`을 사용한다.
- Universal 3D 템플릿과 한 개의 게임플레이 씬을 사용한다.
- 모든 C# 파일명과 클래스명은 정확히 `h980220_`로 시작한다.
- 입력은 Legacy Input Manager만 사용한다.
- 외부 아트 애셋과 음원은 사용하지 않는다.
- 캐릭터, 적, 맵, 투사체는 Unity 기본 3D 프리미티브와 UI로만 만든다.
- 소리, 파티클, 원형 파동, 공격 사거리 표시는 넣지 않는다.
- 예상 플레이 시간은 초보자 기준 3~4분으로 조정하며, 하드 타이머는 두지 않는다.
- 스테이지는 서로 연결된 세 개의 방으로 구성한다.
- 제출물은 불필요한 생성 폴더를 제외하여 총 100MB 미만으로 유지한다.

## 2. 핵심 게임 루프

1. 시작 화면에서 조작법을 확인하고 Enter로 시작한다.
2. A 또는 D로 첫 다리를 들어 리듬 사이클을 시작한다.
3. 들린 발이 착지하기 직전에 반대쪽 키를 누르면 다음 발이 들리고 전진이 이어진다.
4. 좌우 방향키로 몸을 회전하며 적에게 접근한다.
5. Space로 캐릭터 정면에 보라색 Sphere 바이러스 투사체를 발사한다.
6. 적을 필요한 횟수만큼 맞히면 즉시 감염된다.
7. 방 안의 적이 모두 감염되면 다음 방의 문이 열린다.
8. 세 번째 방까지 모두 감염시키면 승리한다.
9. 진행 중 치료제 공격을 세 번 맞으면 바이러스가 치료되어 패배한다.

감염된 적은 공격과 추격을 멈추고 그 자리에서 절차적 호팍 동작을 반복한다. 지나온 방마다 춤추는 적이 남아 플레이 결과를 공간에 축적한다.

## 3. 플레이어 조작과 리듬 이동

### 3.1 입력

- `A`: 왼쪽 다리를 든다.
- `D`: 오른쪽 다리를 든다.
- `LeftArrow`: 캐릭터를 왼쪽으로 회전한다.
- `RightArrow`: 캐릭터를 오른쪽으로 회전한다.
- `Space`: 보라색 바이러스 투사체를 발사한다.
- `Enter`: 시작 화면에서 게임을 시작한다.
- `R`: 승리 또는 패배 화면에서 게임을 재시작한다.

마우스 입력, 새 Input System, Input Actions 에셋은 사용하지 않는다. 구현은 `Input.GetKey`, `Input.GetKeyDown`, `KeyCode`를 사용한다. Unity의 Active Input Handling은 기존 Input Manager 방식으로 설정한다.

### 3.2 리듬 판정

중립 상태에서 처음 누른 A 또는 D는 해당 다리를 들고 첫 사이클을 시작한다. 이 첫 입력만으로는 전진하지 않는다. 들린 발은 설정된 시간 동안 내려오며, 착지 직전의 성공 구간 안에서 반대쪽 키가 입력되면 성공으로 판정한다.

성공 시 다음 동작을 수행한다.

- 현재 발을 착지시킨다.
- 반대쪽 다리를 즉시 들어 다음 사이클을 시작한다.
- 연속 성공 횟수를 1 증가시킨다.
- 계산된 속도로 한 발 사이클 동안 정면 이동을 유지한다.

같은 발을 연속으로 누르거나, 너무 이르게 누르거나, 성공 구간 안에 반대 발 입력이 없으면 실패다. 실패 시 피해나 넘어짐은 발생하지 않는다. 해당 발걸음의 추진을 잃고 연속 성공 횟수가 0으로 초기화되며, 캐릭터는 짧게 어색한 자세로 착지한다. 다음 A 또는 D 입력으로 즉시 새 사이클을 시작할 수 있다.

초기 튜닝 기준은 발 사이클 약 0.5초, 착지 전 성공 구간 약 0.15~0.2초다. 이 수치는 플레이 테스트를 위해 Inspector에서 조정 가능해야 한다.

### 3.3 이동 속도 증가

연속 성공에 따른 속도는 선형으로 증가하고 최고 속도에서 제한한다.

`현재 속도 = Lerp(기본 이동 속도, 최고 이동 속도, Clamp01(연속 성공 횟수 / 최고 속도 도달 성공 횟수))`

다음 값을 `h980220_PlayerRhythmController`의 Inspector에서 조정할 수 있게 한다.

- 기본 이동 속도
- 최고 이동 속도
- 최고 이동 속도에 도달하기까지 필요한 연속 성공 횟수
- 한 발 사이클 시간
- 착지 직전 성공 구간 길이
- 좌우 회전 속도

최고 속도 도달 성공 횟수는 최소 1로 제한한다. 박자 실패 시 연속 성공 횟수와 이동 속도 상승분은 초기화된다. 공격과 회전은 현재 리듬 성공 여부와 관계없이 항상 사용할 수 있다.

## 4. 플레이어 캐릭터와 상태 표현

플레이어는 총 여섯 개의 육면체로 구성한다.

- 머리 육면체 1개
- 몸통 육면체 1개
- 왼쪽 허벅지와 종아리 육면체 각 1개
- 오른쪽 허벅지와 종아리 육면체 각 1개

별도의 발 오브젝트는 사용하지 않는다. 다리는 부모-자식 Transform 구조로 연결하고 Animator나 외부 애니메이션 없이 회전과 위치 보간으로 움직인다. A/D 입력에 대응하는 허벅지와 종아리의 자세가 명확히 달라져야 한다. 플레이어는 화면 효과가 아니라 다리 움직임만 보고 다음 입력 시점을 읽는다.

플레이어는 처음에 강한 보라색 감염 상태다. 치료제에 맞을 때마다 다음 두 표현을 동시에 갱신한다.

- 화면의 보라색 감염도 세 칸 중 한 칸을 제거한다.
- 플레이어 머리와 몸통의 보라색을 한 단계 옅게 만든다.

세 번째 피격으로 감염도가 0이 되면 플레이어 색이 평범한 색으로 돌아가고 호팍 동작과 입력이 멈춘다. 이후 패배 화면을 표시한다.

## 5. 카메라

카메라는 플레이어 뒤쪽 위에서 내려다보는 3인칭 자동 추적 시점이다. 플레이어가 좌우 방향키로 회전하면 카메라가 약간의 지연을 두고 같은 방향으로 따라간다. 마우스로 카메라를 조작하지 않는다.

두 번째 방의 벽과 세 번째 방의 기둥 때문에 플레이어가 가려지지 않도록 일반적인 어깨 시점보다 높게 배치한다. 맵 구조 자체도 카메라와 캐릭터 사이를 막는 높은 천장이나 복잡한 구조를 사용하지 않는다.

## 6. 공격과 감염

Space를 누르면 플레이어 정면에서 보라색 Sphere 투사체가 발사된다. 투사체는 직선으로 이동하며 사거리가 짧다. 정해진 거리까지 이동하거나 적 또는 벽에 충돌하면 제거한다.

공격의 위력, 크기, 사거리와 발사 간격은 현재 리듬이나 연속 성공 횟수에 영향받지 않는다. 공격 사거리를 선, 원, 조준선 또는 HUD로 표시하지 않는다. 날아가는 보라색 Sphere 자체만 공격 방향과 도달 범위를 학습시키는 피드백으로 사용한다.

일반 적과 원거리 적은 한 발에 감염된다. 엘리트 적은 세 발에 감염되며, 피격할 때마다 몸 표면의 보라색 비율이 단계적으로 증가한다. 감염이 완료된 적은 충돌 피해, 치료제 발사, 추격을 모두 중지하고 방의 남은 적 수에서 정확히 한 번만 제외된다.

## 7. 적과 치료제

모든 적의 공격은 플레이어를 죽이는 공격이 아니라 호팍 바이러스를 치료하는 치료제다.

### 7.1 일반 육면체

- 단일 육면체 형태다.
- 플레이어를 천천히 추격한다.
- 플레이어에게 접촉하면 치료제를 1회 주입한 것으로 처리한다.
- 보라색 바이러스 한 발에 감염된다.

### 7.2 원거리 치료 적

- 일반 적보다 길쭉한 육면체 형태로 구분한다.
- 현재 위치를 유지하며 플레이어를 바라본다.
- 일정 간격으로 밝은색 Sphere 치료제 투사체를 발사한다.
- 보라색 바이러스 한 발에 감염된다.

### 7.3 엘리트 치료 적

- 일반 적보다 큰 육면체 형태다.
- 느리게 추격하면서 일정 간격으로 치료제 투사체도 발사한다.
- 보라색 바이러스 세 발에 감염된다.
- 피격 단계에 따라 몸이 0%, 33%, 66%, 100%에 가까운 보라색으로 변한다.

접촉 공격이나 치료제 투사체에 피격되면 플레이어는 뒤로 밀려나며 짧은 무적 상태가 된다. 무적 중에는 추가 치료제를 받지 않는다. 한 번의 접촉이 여러 프레임에 걸쳐 중복 피격으로 계산되지 않아야 한다.

## 8. 세 개의 연결된 방

모든 방은 한 씬 안에 있고 문으로 연결된다. 현재 방의 모든 적을 감염시키면 다음 문이 열린다. 이전 방의 감염된 적은 제거하지 않고 춤추는 상태로 남긴다.

### 8.1 1번 방: 감염 광장

- 예상 시간: 45~60초
- 넓고 장애물이 없는 직사각형 공간
- 일반 육면체 3마리
- 목적: A/D 이동, 좌우 회전, 짧은 사거리 공격을 안전하게 학습

### 8.2 2번 방: 치료 통로

- 예상 시간: 60~90초
- 기둥과 벽으로 만든 단순한 지그재그 통로
- 일반 육면체 2마리, 원거리 치료 적 2마리
- 목적: 벽을 엄폐물로 사용하며 좁은 공간에서 이동 방향을 조절하고 원거리 적에게 접근

### 8.3 3번 방: 최종 치료실

- 예상 시간: 90~120초
- 원형 경기장
- 중앙 주변에 낮고 굵은 기둥 4개를 원형으로 배치
- 일반 육면체 2마리, 엘리트 치료 적 1마리
- 기둥 사이 간격은 최고 속도로 크게 선회할 수 있을 만큼 넓게 유지
- 목적: 기둥으로 치료제 투사체를 막고 추격자를 한쪽으로 유도한 뒤 엘리트에게 세 번 접근해 감염

세 번째 방의 모든 적을 감염시키면 모든 적이 계속 춤추고, 카메라가 조금 멀어지며 `HOPAK VIRUS SPREAD COMPLETE`를 표시한다.

## 9. UI와 게임 흐름

### 9.1 시작 화면

다음 내용만 표시한다.

- `HOPAK VIRUS`
- `A / D: 왼발 / 오른발`
- `← / →: 회전`
- `Space: 바이러스 발사`
- `Enter: 시작`

### 9.2 플레이 HUD

- 화면 한쪽에 보라색 감염도 3칸
- 현재 방 `1/3`, `2/3`, `3/3`

리듬 성공 여부, 연속 성공 횟수, 발 타이밍, 공격 사거리와 조준선은 표시하지 않는다.

### 9.3 결과 화면

- 승리: `HOPAK VIRUS SPREAD COMPLETE`
- 패배: `CURED...`
- 공통: `R: RESTART`

별도 일시정지, 설정, 옵션 메뉴는 만들지 않는다.

## 10. 시각 원칙

게임에 사용하는 모든 모델은 Unity 기본 프리미티브다. 단색 URP Material로 역할을 구분하며 외부 텍스처, 모델, 애니메이션, 아이콘, 음원과 파티클을 사용하지 않는다.

- 플레이어와 바이러스: 보라색
- 치료 전 적: 밝은 청록색
- 치료제 투사체: 흰색
- 감염된 적: 보라색
- 벽과 바닥: 회색 계열의 낮은 채도 단색

리듬의 성공과 실패는 다리 자세, 실제 전진 여부, 짧은 휘청임만으로 표현한다. 원형 파동, 화면 플래시, 사거리 표시, 소리를 보조 피드백으로 사용하지 않는다.

## 11. 코드 구조

모든 MonoBehaviour 파일명과 클래스명은 일치하며 `h980220_` 접두어를 사용한다.

- `h980220_PlayerRhythmController.cs`: Legacy 입력, 리듬 상태, 전진, 회전, 네 다리 파츠 자세
- `h980220_PlayerCombat.cs`: Space 입력과 바이러스 발사
- `h980220_PlayerInfection.cs`: 감염도, 피격 무적, 넉백, 플레이어 색상, HUD 감염도, 패배 요청
- `h980220_FollowCamera.cs`: 높은 3인칭 자동 추적 카메라
- `h980220_EnemyController.cs`: 적 종류별 추격, 접촉 치료, 원거리 치료, 감염 명중 횟수, 감염 춤
- `h980220_Projectile.cs`: 바이러스와 치료제 투사체의 이동, 소유자 판별, 충돌, 수명 종료
- `h980220_RoomController.cs`: 현재 방의 미감염 적 수, 문 개방, 방 완료 통지
- `h980220_GameManager.cs`: 시작, 방 순서, 승리, 패배, 재시작과 입력 잠금

주요 데이터 흐름은 다음과 같다.

- `A/D → 리듬 판정 → 다리 자세 → 연속 성공 수 → 이동 속도`
- `Space → 바이러스 생성 → 적 충돌 → 감염 단계 증가 → 방의 남은 적 감소 → 문 개방`
- `적 접촉/치료제 충돌 → 무적 확인 → 감염도 감소 → 색상/HUD 갱신 → 0이면 패배`
- `세 번째 방 완료 → 전체 입력 잠금 → 승리 연출 → 재시작 대기`

기본 템플릿에 포함된 `Readme.cs`, `ReadmeEditor.cs` 등 접두어가 없는 예제 C# 스크립트는 제거한다. 사용하지 않는 `InputSystem_Actions.inputactions`도 제거한다.

## 12. 오류 방지

- 게임 시작 전과 승리·패배 후에는 플레이 입력을 무시한다.
- 피격 무적으로 접촉 Collider가 여러 프레임에 걸쳐 중복 치료를 적용하지 않게 한다.
- 감염 완료 플래그로 같은 적이 방의 남은 적 수에서 두 번 빠지지 않게 한다.
- 투사체에는 거리 또는 수명 제한을 두어 씬에 계속 쌓이지 않게 한다.
- 발 상태는 중립, 왼발 들림, 오른발 들림으로 제한해 양발이 동시에 들리는 잘못된 상태를 방지한다.
- 최고 속도 도달 성공 횟수는 1 이상, 최고 이동 속도는 기본 이동 속도 이상으로 검증한다.
- 방 순서는 한 방향 문으로 통제하여 완료하지 않은 방을 건너뛰지 못하게 한다.
- 재시작은 현재 씬을 새로 로드해 적 수, 문, 감염도와 리듬 상태를 완전히 초기화한다.

## 13. 검증 기준

### 13.1 자동 검증

테스트 C# 클래스와 파일에도 `h980220_` 접두어를 사용한다.

- 연속 성공 횟수가 설정값에 도달하면 정확히 최고 이동 속도가 되는지 검사한다.
- 연속 성공 횟수가 설정값을 넘겨도 최고 속도를 초과하지 않는지 검사한다.
- 리듬 실패 시 연속 성공 수와 속도 상승분이 초기화되는지 검사한다.
- 치료제 세 번으로만 패배하며 무적 중 중복 피격이 무시되는지 검사한다.
- 일반·원거리 적은 한 발, 엘리트 적은 세 발에 감염되는지 검사한다.
- 감염된 적이 방의 남은 적 수에서 한 번만 제외되는지 검사한다.

### 13.2 수동 플레이 테스트

- 처음 플레이하는 사람이 시작 후 30초 안에 전진 방법을 이해한다.
- 박자 실패가 긴 정지나 반복 사망보다 짧은 휘청임으로 느껴진다.
- 광장, 통로, 기둥 경기장의 전투 방식이 서로 다르게 느껴진다.
- 짧은 공격 사거리를 별도 표시 없이 투사체 움직임으로 학습할 수 있다.
- 초보자가 세 방을 5분 이내에 완료할 수 있다.
- 목표 플레이 시간 중앙값은 3~4분이다.
- 승리, 패배, 재시작을 반복해도 상태가 꼬이거나 오류가 발생하지 않는다.
- 플레이어, 치료제, 바이러스, 감염된 적이 색상과 형태로 구분된다.

## 14. 제출 전 점검

- 모든 C# 파일명과 클래스명에서 `h980220_` 접두어를 검사한다.
- Active Input Handling과 코드 사용처가 Legacy Input Manager인지 검사한다.
- 외부 아트, 모델, 텍스처, 음원, 파티클이 포함되지 않았는지 검사한다.
- 게임을 처음부터 승리와 패배까지 각각 실행하고 R 재시작을 확인한다.
- Windows 빌드 또는 요구 제출 형식에서 정상 실행을 확인한다.
- 제출 압축 파일에서 `Library`, `Temp`, `Logs`, `obj`, IDE 캐시와 불필요한 심볼을 제외한다.
- 최종 제출물의 총용량이 100MB 미만인지 확인한다.
