# HOPAK VIRUS 몸통 출렁임 설계

## 목표

호팍 동작에서 다리만 움직이던 문제를 보완한다. 발을 드는 리듬과 동시에 `Torso`가 아래로 눌리고 든 다리 쪽으로 기울어, 한 동작이 전신의 반동처럼 읽히게 한다.

플레이어의 머리는 사용자가 의도적으로 제거했다. 정식 플레이어 비주얼은 `Torso`, `LeftThigh`, `LeftShin`, `RightThigh`, `RightShin`의 Cube 5개다. `Head`를 다시 만들지 않는다.

## 동작

- 기존 다리 포즈와 같은 `sin(normalizedStep * PI)` 곡선을 사용한다.
- 발을 막 들기 시작하거나 착지했을 때 출렁임은 0이다.
- 발이 가장 높을 때 `Torso`는 `torsoBobHeight`만큼 아래로 내려간다.
- 왼발을 들면 `Torso`가 왼쪽으로 `torsoLeanDegrees`만큼 기울고, 오른발은 반대 방향으로 기운다.
- 기본값은 `torsoBobHeight = 0.18m`, `torsoLeanDegrees = 12도`로 하며 Inspector에서 조정 가능하게 한다.
- 리듬이 멈추거나 플레이어 입력이 비활성화되면 `Torso`는 정확히 원래 위치와 회전으로 돌아간다.

## 기존 시스템과의 경계

- 플레이어 루트와 `CharacterController`는 움직이지 않는다. 이동, 충돌, 넉백, 카메라 기준점은 기존과 같다.
- `Torso`의 현재 `localPosition`과 `localRotation`을 `Awake`에서 기준 자세로 저장하고 그 기준에 상대적으로 포즈를 적용한다. 사용자가 수정한 Torso 배치와 크기를 고정값으로 덮어쓰지 않는다.
- 직렬화된 Torso 참조가 없으면 플레이어 자식 중 이름이 정확히 `Torso`인 Transform을 찾는다. 현재 사용자 씬을 다시 생성하거나 수동으로 재배선하지 않아도 동작해야 한다.
- 공격, 사거리, 감염, 적, 방 진행, 입력 방식에는 새 동작을 추가하지 않는다.

## 씬과 빌드 보호

- 현재 `Assets/HOPAK VIRUS/Scenes/HOPAK VIRUS.unity`에는 사용자의 미커밋 수정이 있다. 구현과 검증에서 이 씬을 재생성하거나 되돌리거나 정리하지 않는다.
- 미래에 명시적으로 씬 빌더를 실행할 경우 생성되는 플레이어도 Head 없는 Cube 5개 구조여야 한다.
- Windows 빌드는 현재 저장된 씬을 사용해야 하며, 빌드 과정이 자동으로 `BuildScene()`을 호출해 사용자 씬을 덮어쓰면 안 된다. 씬 재생성은 `RebuildScene()`을 명시적으로 호출했을 때만 수행한다.

## 코드 구조

- 순수 포즈 계산 결과에 Torso의 세로 오프셋과 Z축 기울기를 추가한다.
- `h980220_PlayerRhythmController`는 다리 포즈와 같은 프레임에 Torso 포즈를 적용한다.
- Torso 기준 자세 캡처, 포즈 적용, 입력 비활성 시 복원을 컨트롤러가 담당한다.
- 모든 새 C# 파일과 선언 타입은 기존 시험 규칙대로 `h980220_` 접두어를 사용한다.

## 테스트

1. 왼발 최고점에서 Torso가 아래로 내려가고 왼쪽으로 기운다.
2. 오른발 최고점은 같은 높이 반동과 반대 기울기를 만든다.
3. 무동작과 착지 시 Torso 오프셋과 기울기는 0이다.
4. 컨트롤러는 사용자가 배치한 Torso 기준 위치·회전에 상대적으로 포즈를 적용하고 입력 비활성 시 복원한다.
5. 현재 씬을 재생성하지 않은 상태에서 Torso 자동 탐색이 동작한다.
6. 씬 빌더와 구조 테스트의 플레이어 요구 수는 Cube 5개이며 Head가 없다.
7. Windows 빌드 진입점은 씬을 재생성하지 않는다.
8. 기존 EditMode와 PlayMode 회귀 테스트가 모두 통과한다.

## 범위 밖

- 머리 재생성
- 캐릭터 루트 점프나 물리 스프링
- 손, 팔, 골반 등 새 비주얼 세그먼트
- 사운드, 파티클, 원형 파동, 사거리 표시
- 사용자가 수정한 방 구조와 씬 오브젝트의 재배치
